# 캐릭터 걷기 에셋 규격

3D로 제작해 2D 스프라이트로 내보내는 것을 전제로 한다. 런타임은 계속 2D이고
three.js 같은 3D 라이브러리는 쓰지 않는다. 3D는 제작 단계에만 쓴다.

## 왜 3D로 제작하는가

지금 캐릭터는 낱장 생성 이미지라 세 가지가 동시에 막혀 있다.

- **입체감** — 배경은 렌더된 로우폴리 3D인데 캐릭터만 평면이라 겉돈다.
- **걷기** — 8장이 있어도 걷기 사이클이 아니다. 아래 "왜 지금 그림이 안 되는가" 참고.
- **의상** — `CharacterEquipment`를 레이어 렌더러로 확장하려면 의상 하나당
  4방향 × 8프레임 = 32장이 필요하다. 6슬롯에 아이템이 몇 개씩만 있어도 수백 장이다.

리그에서 렌더하면 셋이 한 번에 풀린다. 의상은 모델을 한 번 만들면 같은 걷기
애니메이션에 얹어 32장이 자동으로 나온다.

## 왜 지금 그림이 안 되는가

각 프레임에서 발 근처 불투명 픽셀의 가로 폭(다리 벌어짐)을 몸 폭 대비로 측정한 값이다.

| 방향 | 프레임별 다리 벌어짐 | 변화폭 |
| --- | --- | --- |
| front | 30.9, 34.7, 34.0, 37.0 | 6.1%p |
| back | 35.2, 37.4, 36.6, 40.7, 34.0, 34.8, 34.1, 38.6 | 6.7%p |
| left | 69.1, 70.5, 64.0, 71.2, 72.0, 74.6, 69.4, 73.2 | 10.6%p |
| right | 58.8, 57.4, 59.0, 69.5, 54.5, 53.5, 53.2, 69.5 | 16.3%p |

정상적인 걷기는 다리를 모은 순간(거의 0%)부터 가장 벌어진 순간(35%p 이상)까지
오간다. 지금은 8장 내내 비슷하게 벌어진 상태로 고정돼 있다. **다리가 모이는
프레임(passing)이 한 장도 없다.** 그래서 `sequence`가 2장으로 줄어 있다.

## 프레임 구성

방향당 8장, 걷기 한 사이클. 파일명은 `01.png` ~ `08.png`.

| # | 단계 | 다리 벌어짐 | 설명 |
| --- | --- | --- | --- |
| 01 | contact | 35%p 이상 | 앞발 뒤꿈치가 닿는 순간. 가장 벌어진다 |
| 02 | down | 중간 | 체중이 실리며 몸이 가장 낮아진다 |
| 03 | **passing** | **0~5%** | 뒷다리가 앞다리를 스쳐 지나간다. 다리가 모인다 |
| 04 | up | 중간 | 몸이 가장 높다 |
| 05 | contact | 35%p 이상 | 반대 발로 01 반복 |
| 06 | down | 중간 | |
| 07 | **passing** | **0~5%** | |
| 08 | up | 중간 | |

08에서 01로 이어져야 하므로 **루프가 맞아야 한다.** 03과 07이 지금 없는 프레임이고,
이 두 장이 있어야 "걷는다"로 읽힌다.

## 렌더 설정

| 항목 | 값 |
| --- | --- |
| 방향 | front / back / left / right 4종 |
| 카메라 | **정사영(Orthographic)**. 원근 왜곡이 있으면 스프라이트로 못 쓴다 |
| 카메라 고도각 | **약 30°** (아래 "고도각을 어떻게 구했나" 참고) |
| 방향 만들기 | 카메라는 고정하고 캐릭터를 90°씩 돌린다 |
| 광원 | **오른쪽 위**, 모든 프레임·모든 방향 동일 |
| 형식 | 투명 배경 PNG |
| 해상도 | 캐릭터 높이 400px 정도면 충분 (화면에서 약 75px로 그려진다) |

광원 방향은 코드와 맞물려 있다. 그림자는 왼쪽 아래로 눕고 햇빛 오버레이는
오른쪽 위에서 오도록 `game.css`에 박혀 있다.

## 색 규격

배경 잔디와 캐릭터의 HSL 분포를 실측한 결과다.

| | 배경 잔디 | 현재 캐릭터 |
| --- | --- | --- |
| 명도 하위 2% | 0.547 | 0.267 |
| 명도 중앙값 | 0.669 | 0.520 |
| 채도 상위 10% | 0.561 | 0.944 |

배경 잔디는 명도가 **0.55~0.69의 좁은 띠** 안에만 있다. 어두운 색 자체가 없다.
배경에 없는 명도대를 캐릭터만 가지는 것이 색으로 튀어 보이는 주된 이유다.

- **명도 하한 0.35 이상** — 머리카락·신발 같은 어두운 덩어리를 이보다 어둡게 만들지 않는다
- **채도 상한 0.6 이하** — 지금 파란 반바지가 0.94로 배경 팔레트를 벗어나 있다
- **윤곽선 없음** — 배경에 윤곽선이 없다
- **그림자를 굽지 말 것** — 코드가 넣는다. 그림자가 구워져 있으면 이중으로 보인다

색을 이대로 맞추면 `game.css`의 보정 필터(`saturate`/`contrast`/`brightness`)와
반사광 오버레이는 걷어내도 된다. 지금은 규격에 안 맞는 그림을 런타임에서
보정하고 있는 것이다.

## 파이프라인

```
character_master.png
  → ① 이미지→3D 로 메시 뽑기 (초안으로만. 정리 필요)
  → ② Blender 에서 메시·재질 정리
  → ③ Mixamo 자동 리깅 + 걷기 애니메이션
  → ④ Blender 에서 4방향 정사영 렌더, 사이클을 8등분
  → ⑤ src/assets/character/walk/{front,back,left,right}/01~08.png
  → ⑥ npm run pack-sprites
```

③에서 걷기 애니메이션을 직접 만들 필요는 없다. Mixamo의 기성 걷기를 가져다
쓰면 된다. 치비 비율이라 보정은 좀 필요하다.

## 넣은 뒤 확인하는 법

`npm run pack-sprites`가 프레임별 발 위상과 판정을 출력한다.

```
walk-left.webp  ...  8장  위상폭 1.9%  재생 [6, 0]
   발 위상   0.8  -1.2  -0.7  -0.5  -0.5  -0.2  -0.8  -0.7
   → 사이클 아님(한쪽 발만 계속 아래). 차이 큰 두 장만 재생
```

발 위상은 좌우 발의 높이 차다. 양수면 오른발이, 음수면 왼발이 아래에 있다.
**제대로 된 사이클이면 이 값이 양수와 음수를 뚜렷하게 오간다.** 위 출력은
left 8장이 전부 한쪽에 몰려 있어 사이클로 인정되지 않은 예다.

`→ 걷기 사이클. 전부 재생`이 나오면 제대로 들어온 것이다.

## 새 프레임이 들어온 뒤 할 일

`pack-sprites`가 `characterFrames.ts`를 다시 쓰므로 코드는 대부분 그대로지만,
다음 세 가지는 손봐야 한다.

- **`WALK_CONFIG.fps`** — 지금 3이다. 사이클이 아니라 8fps로 돌리면 떠는 것처럼
  보여서 낮춰 둔 값이다. 제대로 된 사이클이 오면 8~10으로 올린다.
- **`WALK_CONFIG.speed`** — 지금 0.032다. 보폭과 무관하게 보기 좋은 값으로만
  잡아 둔 것이다. 한 걸음에 나아가는 거리를 재서 `speed = 보폭 × fps / 2`로 맞추면
  발 미끄러짐이 사라진다.
- **`BOB_PERCENT`** — 지금 1.4다. 2프레임 토글의 빈 구간을 메우려고 넣은 것이라,
  진짜 사이클에는 상하 운동이 이미 들어 있으므로 줄이거나 없앤다.

`sideExpressions.ts`의 `SIDE_NECK_ANCHORS`는 걷기 원본의 목 위치를 실측한 값이라
**새 프레임에서 다시 재야 한다.** 다만 3D로 렌더하면 표정도 함께 렌더할 수 있어,
머리를 덮어씌우는 이 방식 자체가 필요 없어질 수 있다.

## 고도각을 어떻게 구했나

배경 그림의 원형 디딤돌은 카메라가 기울어진 만큼 타원으로 눌려 보인다.
눌린 비율이 `sin(고도각)`이므로 여기서 각도를 역산할 수 있다.

디딤돌 5개를 실측한 결과다.

| 가로 | 세로 | 비율 | 고도각 |
| --- | --- | --- | --- |
| 69 | 34 | 0.493 | 29.5° |
| 68 | 32 | 0.471 | 28.1° |
| 57 | 31 | 0.544 | 33.0° |
| 56 | 30 | 0.536 | 32.4° |
| 47 | 20 | 0.426 | 25.2° |

평균 29.6°. 편차는 디딤돌이 풀에 가려 경계가 정확히 안 잡힌 탓이다.
**30°로 두고, 배경 이미지를 뷰포트에 깔아 눈으로 한 번 더 맞추면 된다.**

좌우 회전(yaw)은 아무 값이나 괜찮다. 캐릭터만 투명 배경에 렌더하고 방향은
캐릭터를 90°씩 돌려 만들기 때문에, 절대 각도가 아니라 **네 방향이 정확히
90°씩 차이 나는 것**만 지키면 된다.
